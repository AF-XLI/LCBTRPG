# LCBTRPG戦闘システム

GitHub Pages(静的ホスティング)+ Firebase Realtime Database(無料のSparkプラン)で動く、最大8人程度向けの戦闘進行サイトです。ビルド作業は不要で、ファイルをそのまま置くだけで動きます。

## ファイル構成

このフォルダ(`battle/`)が戦闘システムです。Firebase の接続情報(`config.js`)、ログイン画面(メインページ)、画像(`image/`)は、キャラクターシートと共用するため、一つ上の階層にあります(`../config.js`、`../image/` として読み込みます)。

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面の骨組み |
| `style.css` | 見た目(PC優先。スマホは暫定) |
| `js/logic.js` | ルール計算(画面に依存しない純粋なロジック。Node でも動作) |
| `js/store.js` | 共有(Firebase / ローカル)の通信部分 |
| `js/ui.js` | 画面の組み立て(HTML文字列を返すだけ) |
| `js/app.js` | 操作・同期・矢印/演出の制御 |
| `sample/party.json`, `sample/enemies.json` | サンプルデータ |
| `test/sim.js` | 自動対戦試験(`node test/sim.js`) |

## まず動かす(Firebase なし)

一つ上の階層の `config.js` が空のままだと「ローカルモード」になり、同じブラウザの複数タブ間だけで同期します。操作の確認用です。
`index.html` をブラウザで開く(画像を表示するには、リポジトリの一番上のフォルダで `python3 -m http.server` を実行し、`http://localhost:8000/battle/` を開く)→ ルームIDを入れて入室 → GMで入ると準備パネルが出ます。

※ サンプルの自動読み込みボタンは、`file://` で直接開いた場合は動きません。公開後のURL、またはローカルサーバー経由でお試しください(JSONの貼り付けはどちらでも可)。

## Firebase・ログイン・公開

Firebase の設定、ログインと役職の登録、GitHub Pages での公開は、リポジトリの一番上の [README.md](../README.md) にまとめています。戦闘システムのページは、公開後は `…/battle/` で開けます(卓の参加者には、ルームIDを伝えてください。`…/battle/?room=ルームID` のURLを共有しても入室できます)。GMとプレイヤーとして入るには、先にメインページでログインしてください(観戦はログイン不要です)。

## 遊び方

役割は入室時に選びます。

- **GM**: 準備パネルで味方/敵のJSONを読み込み、戦闘を開始します。敵の行動決定(敵のスキル駒を押し、次に味方の駒を押して対象を選択。敵の防御・回避は「合わせる味方」を選びます。反撃は対象なし。スキルの手動変更も可)、ラウンドの進行(戦闘開始 → 1手進める/自動進行 → 次のラウンド)、体力・精神力・状態・E.G.O・復帰などの手動補助を行います。
- **プレイヤー**: 上部で操作キャラを選び、自分の駒(速度の上)を押してスキルを選択 → 敵のスキル駒を押して対象を決める。対象を決めた時点で確定します(確定ボタンはありません。スキルや対象は選び直せます)。守備(防御・回避)も、合わせる敵の攻撃スキル枠を選びます。反撃も対象(敵の攻撃スキル枠)を選んで矢印を引きますが、発動は最初に攻撃を受けた相手のままで、対象は発動に影響しません。味方全員が確定するまで、GMは戦闘を開始できません。
- **観戦**: 見るだけです。

1ラウンドの流れ: `敵の行動決定(GM)` → `味方の行動選択` → `戦闘処理(速度順)` → `ラウンド終了`。

画面の見かた(PC版。スマホ版は後日調整予定で、現在は縦に並べて使える程度です):

- 上部の赤い帯: 中央にラウンドと段階、右に「確定 x / y」と、GMには次に押すボタン(戦闘開始 / 1手進める / 次のラウンドへ)。
- 敵は上段に、名前・体力バー・精神力バー・立ち絵・スキル駒の順で並びます。異常体は、スキル駒を押すと全体の体力バーが、その部位の耐久バーと精神力バーに切り替わります(余白を押すと戻る)。
- 味方は下段に速度の速い順で並び、スキル駒(未選択はブランク)・速度(黄色)・体力リング(左下の数字が体力、右下の丸が精神力)・確定状況が出ます。
- 矢印: 金=マッチ(矢じりがぶつかる位置に火花。守備を合わせた場合は火花なし)/ 赤=敵の一方攻撃 / 水色=味方の一方攻撃。右パネルの「矢印の表示」で切り替えられます。
- 敵のスキル駒や部位を押すと詳細が出ます。体力バーの黄色い線は混乱の閾値です。
- ログは戦闘開始時に窓で開き、そのラウンドの分だけを表示します(右上の「ログ」でも開閉できます)。
- 敵の速度は、敵スキル駒の上に表示されます。
- 敵の並びは準備パネルの「敵の配置(左から)」で決め、戦闘中は動きません。撃破された敵は詰めて表示されます。

## JSON の形式

味方は `sample/party.json`、敵は `sample/enemies.json` を見本にしてください。味方・敵ともスキルや効果の書き方はキャラクターシートのデータ(`data/<囚人ID>/identities.json`・`egos.json`)と同じ形式で、戦闘で使う値(コインの並び・攻撃/守備の区別・効果の処理)は読み込み時に自動で求めます。効果の種類やタイミングの一覧は `shared/effects.js` にあり、`node tools/validate.js` でデータの誤りを検査できます。

### 味方

`id, name, hp(最大体力), sp(精神力), speed:[最小,最大], thr:[混乱区間(%)…], resist(耐性の倍率), skills[], defense, passive, support, egos[]`

- `skills` はスキル1〜3(`tier` で区別)、`defense` が守備です。守備の `type` は `guard`(防御)・`evade`(回避)・`counter`(反撃。反撃の攻撃タイプは `phys` で指定)です。攻撃スキルの `type` は `slash` / `pierce` / `blunt` です。
- `resist` は `{"slash": 2, "pierce": 0.5}` のように倍率で書き、書かなかったものは1(普通)です。2=脆弱、0.75=抵抗、0.5=耐性です。
- `thr` は混乱区間で、最大体力に対する%です(例: グレイは `[75, 50]`)。省略すると混乱しません。
- E.G.O: `egos:[{rank, name, sin, type, base, coin, coins, weight, sp, cost, resist, effects, passive, corrosion}]`
  - `rank` は `ZAYIN` / `TETH` / `HE` / `WAW` / `ALEPH` で、同じランクは重複できません(最大5種類)。`sp` は精神消耗量、`cost` は必要資源で `{"pride": 3, "sloth": 2}` の形です。`resist` は罪悪属性の倍率です。
  - E.G.O自体が覚醒スキルで、`corrosion` が侵食スキルです(囚人E.G.Oは `prisoner:true` にして `corrosion` なし)。どちらもスキル枠はスキル3のものを使い、罪悪属性があります。`corrosion` に `blind:true` を付けると [敵味方識別不可] です。
  - 使い方: 守備と同じく、先に引いた方の手札を置き換えて使用し、その手札は消費されます。覚醒=資源・精神力とも1倍、侵食=資源1倍・精神力1.5倍です。`blind` の侵食スキルは、資源の1.5倍(切り捨て)が足りていれば自動で味方を除外し(資源1.5倍を支払う)、足りなければ味方を含めて資源1倍で使います。資源が1倍分も足りないものは暗くなって選べません。
  - 資源は選択時に支払い、選び直し・不発(取り消し・混乱など)で返却します。精神力は[攻撃前]に支払います。マッチに負けた場合は使用した扱いで、返却しません。E.G.Oスキルの使用では資源は増えません。
  - 耐性の区分は、普通(×1.0)・脆弱(×2.0・`weak`)・抵抗(×0.75・`resist`)・耐性(×0.5・`strong`)です。耐性が1.0未満の補正は(倍率-1)の半分なので、抵抗は-0.125、耐性は-0.25です。E.G.Oの `resist` は `{weak:[…], resist:[…], strong:[…]}` で、同じ属性が複数に書かれた場合は脆弱、耐性、抵抗の順に優先します。
  - 耐性は、戦闘開始時は装備中のZAYINのE.G.Oの `resist` を参照し、使用したE.G.Oの耐性に切り替わります(戦闘中は続き、別のE.G.Oを使うとそちらに切り替わります)。
  - `passive: {name, effects[]}` は、対応するE.G.Oを使用した次のラウンドから、戦闘中ずっと発動します(E.G.O侵食時はそのラウンドから)。バフの位置の先頭に、数値のない「E.G.O」のアイコンを表示します。
  - [敵味方識別不可]: メインターゲットは自分以外の敵のスキル駒(ブランク駒を含む)と生存している味方から完全にランダムです。サブターゲットは、敵か味方かをランダムに決め、敵なら既存の選び方、味方ならランダムです。味方を除外する使い方では、敵だけが対象です。
  - E.G.O侵食: 囚人E.G.O以外を装備して精神力が-45になると、パニックの代わりに次のラウンドから、最後に使ったE.G.O(なければランダム)の侵食スキルをコストなしで使います(スキル変更不可)。パニックと同様に、-45になったラウンドは通常どおり動け、次のターン開始時に精神力が0に戻ります。
  - 即時E.G.O侵食: E.G.Oの精神力コスト([攻撃前]の支払い)で-45になった場合は、その場でE.G.O侵食になります。覚醒で使っていれば、同じE.G.Oの侵食スキルに切り替えて攻撃します(資源の追加支払いなし。マッチは元のスキルで行います)。メインターゲットは維持し、侵食スキルが [敵味方識別不可] ならサブターゲットを味方を含めて引き直し、そうでなければサブターゲットも維持します。パッシブはそのラウンドから有効で、精神力はラウンド終了時に0へ戻り、次のラウンドの侵食・パニックは起こりません。囚人E.G.Oなど侵食スキルがない場合は元のスキルで攻撃し、次のラウンドに通常のパニック・E.G.O侵食を行います。
- パッシブ・サポートパッシブは `passive: {name, sin, count, effects[]}` と `support: {…}` です(`sin` と `count` は「罪悪属性×n保有」の条件で、`resonance:true` を付けると「×n共鳴」になります)。
  - バトルパッシブ(`passive`)は人格に付随する自己効果で、サポートパッシブ(`support`)は味方全体への効果です(サポートパッシブはパーティ全体で最大4つ。選択の画面は今後、キャラクターシート完成後に考えます)。
  - 画面左の金枠に並びます(パッシブが上、サポートパッシブが下)。`need` と `reso` がないバトルパッシブは常時発動で、左の欄には出しません。
  - `need` は「資源×n保有」の条件で、`{"pride": 3}` のように書きます。足りない間はアイコンが暗くなります(省略すると常に明るい)。
  - `reso` は「罪悪名×n共鳴」の条件で、`{"wrath": 3}` のように書きます。同ラウンドに味方が使う同罪悪のスキルがn個以上で発動し、位置は問わず、戦闘開始時に判定します。`need` と併記すると両方が必要です。
  - `icon` は画像のパスで、省略するとキャラ名の頭文字を表示します。アイコンを押すと説明が出ます。
  - `grants` は戦闘開始時(`combatStart`)などに自動で発動します。条件(`need` / `reso`)は戦闘開始時に判定し、そのラウンド中は固定です。資源は消費しません。発動するとログに「(キャラ名)のパッシブ「(名前)」が発動」と出ます。
  - 付与先は `to:"self"`(持ち主)または `to:"allies"`(生存している味方全員。持ち主を含む)です。

### スキル

`tier, sin(罪悪), type, name, base(基礎威力), coin(コイン1枚の加算), coins(コインの枚数), weight, noMatch, critBonus, effects[]`

- 説明文はデータから自動で作られます(手書きの `text` は不要です)。

- `weight`: 攻撃加重値(2以上で広域攻撃。詳細は「広域攻撃」)。
- `critBonus`: クリティカルが発生したとき、バフ枠のスキル効果に加える%です(例: `20`)。
- `noMatch:true`: 敵のスキル専用で、マッチできないスキルです。攻撃スキルで合わせても一方攻撃になり、守備スキルを合わせた場合は通常どおり有効です(対象変更も可能)。
- スキル差し替え(`replace`)と条件分岐(`branches`)は、効果の種類としては未対応です。必要になった時点で追加します。

### 効果(effects)

スキル・パッシブの効果は `effects` に1効果ずつ並べます。形は `{coin, timing, type, …}` で、表示(キャラクターシートと戦闘の説明)は効果から自動で作られます。

- `coin`: コインの番号(スキルのコイン効果だけ。スキル全体に付く効果は省略します)。
- `timing`: タイミング。`battleEnter`(戦闘突入時)・`battleStart`(戦闘開始時)・`turnStart`(ターン開始時)・`use`(使用時)・`beforeAttack`(攻撃前)・`matchWin`・`matchLose`・`hit`(的中時)・`headsHit`(表面的中時)・`tailsHit`(裏面的中時)・`hpCond` / `spCond`(体力・精神力が条件の時。`cond:{of, op, value, unit}` と、体力は `checkAt`(`beforeDamage` / `afterDamage`)を付けます)。パッシブは省略すると戦闘開始時に発動します。
- `type`: 効果の種類です。
  - `grant`: 状態異常の付与(`status`, `power`, `count`、複数は `items:[{status, power}]`。`target`、`delay:"nextTurn"`、`if:"dispelled"` も使えます)
  - `gain`: 回数の増加(`status`, `count`)
  - `dispel`: デバフの解除(`target`, `count`)。解除可能なデバフからランダムに種類を選び、威力・回数・数値を全て0にします。続けて `then:[…]` に「解除したなら」の効果を書けます。
  - `dmgBonus`: ダメージ量の増加(`percent`, `scope:"allies"`, `when:{targetSp:"lowerThanSelf"}`)
  - `spHeal`: 精神力の回復(`amount`, `when:{self:"noDebuff"}`)
- 新しい効果の種類は、`shared/effects.js` に表示と戦闘用の処理を追加します。未実装の種類をデータに書くと、`tools/validate.js` と読み込み時にエラーになります。

### 内部の効果処理(grants)

次は、`effects` から自動で作られる戦闘エンジン内部の形(`grants`)の説明です。データには書かず、新しい効果の種類を足すときの部品として使います。


`{status, p(威力), c(回数) または v(値), to:"target"|"self"|"allies", when:"(タイミング)", side:"heads"|"tails", coin:N, if:{...}, next:true, dmgPct, perCoin, scope, takenPct}`

付与できるのは、次の種類です(これ以外の効果の種類は、必要になった時点で追加します)。

- 状態の付与: `status` に `p`(威力)・`c`(回数)・`v`(値)を指定します。威力のみ指定して回数が0なら、回数は1になります。
- ダメージ%の加算(ラウンド終了時に消えます。バフ枠の「スキル効果」に、状態(ダメージ量増加など)とは別に足されます):
  - `dmgPct: 5`: 与えるダメージ+5%。`perCoin: 2`: 「スキルの使用者のコイン数×2%」のように、コイン数×% を毎回計算します(パッシブでは、そのラウンドに持ち主が選んだスキルのコイン数)。
  - `scope`: スキルの効果は、そのスキルの攻撃でのみ有効です(`skill`=攻撃全体が既定、`finalCoin`=最後のコインのみ)。使用者自身の与ダメージに掛かり、付与先は指定できません。`round`(そのラウンド中ずっと)はパッシブ専用で、パッシブの既定です。
  - `takenPct: -10`: 受けるダメージ-10%(そのラウンド中)。
  - `dmgIf`: ダメージ%の加算(と `takenPct`)に付ける、攻撃のたびに判定する条件です。`{ "sp": {"of":"target"|"self", "op":"<", "vs":"self"|"target"} }` のように書くと、`vs` で相手側の値と比べます(`hp` も同様)。`self` は効果の持ち主で、`target` はその相手です。数値と比べるなら `v` を使います。例:「自分より精神力の低い対象へのダメージ+15%」は `dmgPct:15, dmgIf:{sp:{of:"target", op:"<", vs:"self"}}`。
  - `perMatch: 3, max: 15`: マッチ1回ごとに+3%(最大+15%)。耐性枠のマッチ回数補正とは別枠です。
  - 振動爆発: `burst: true` で、`to` に指定した対象の振動爆発を起こし、混乱線を振動威力ぶん前進させます(振動の威力・回数は減りません)。「振動回数をX回減少」のような記載は、`status:"vibration"` で `c` に負の値を指定するなど、別の効果として書きます。振幅変換は `convert:"(種類)"` です。通常は的中時(コイン効果)に使います。GMの手動ボタンはありません。
  - 同じ種類の効果は合算されます(例: `dmgPct` が複数あれば足し合わせます)。
- そのほかの効果(いずれもパッシブ用に作ってあり、スキルの `grants` でも使えます):
  - `critPct: 10`: クリティカル発生時のダメージ+10%(バフ枠のスキル効果)。
  - `breathKeep: 50`: クリティカル時に、50%の確率で呼吸回数を消費しません。
  - `matchPower: 1`: マッチ威力+1(そのラウンド中)。`winProbMax: 40` を付けると、そのマッチの勝率が40%以下のときだけ有効です。
  - `heal: 5`: 体力を回復します(味方のみ)。`sp: 5`: 精神力を増減します。
  - `pick: "lowestHp"|"lowestSp"`(`to:"allies"` と併用): 味方から1人だけを選びます。体力が一番少ない人(最大体力の人は除外)、または精神力が一番低い人で、同値は味方の並び順(左)を優先します。
  - `once: true`: そのラウンドに1回だけ発動します(ラウンド開始時にリセット)。
- パッシブの発動タイミングは `combatStart`(戦闘開始時)、`kill`(対象討伐時)、`matchWin`、`matchLose` です。マッチ勝利時・マッチ敗北に付けるダメージ%の加算は、`scope:"skill"` にすると、そのマッチの後の攻撃だけに掛かります。

状態の ID は `burn bleed vibration rupture sinking breath charge trance paralysis bind dmgUp dmgDown fragile protect powerDown quick powerUp ...` です(`js/logic.js` の `STATUS` 参照)。`next:true` は次のラウンドの開始時に付与します。

- コインの番号 `coin` は元のコインの番号で、マッチで先頭から失ったコインの効果は発動しません(例: 1枚目を失うと、元の2枚目が先頭になっても「Ⅰ」の効果は発動しません)。

- `when`(省略時は的中時)は、英語名でも日本語表記でも書けます(`[]` は付けても付けなくても可)。同じタイミングの効果は上に書いたものから順に処理し、同じコインに異なるタイミングの効果を並べても構いません。

  | 英語名 | 日本語表記 | 発動するタイミング |
  | --- | --- | --- |
  | `combatStart` | 戦闘開始時 | GMが開始を押した時 |
  | `firstRound` | 戦闘突入時 | 1ラウンド目のみ。ターン開始時の前 |
  | `roundStart` | ターン開始時 | クイックなどを付与した後、速度抽選の前 |
  | `use` | 使用時 | マッチ・一方攻撃に入る前 |
  | `beforeAttack` | 攻撃前 | 攻撃の直前(マッチした場合はマッチ後) |
  | `matchWin` | マッチ勝利時 | 一方攻撃では発動しない |
  | `matchLose` | マッチ敗北 | マッチ勝利時と同じタイミング |
  | `hit` | 的中時 | 攻撃が当たった時(回避されれば発動しない) |
  | `hit` + `side:"heads"` | 表面的中時 | 対応するコインが表の時 |
  | `hit` + `side:"tails"` | 裏面的中時 | 対応するコインが裏の時 |
  | `kill` | 対象討伐時 | 攻撃で対象を倒した時(自分の陣営以外の対象) |

- `combatStart` `firstRound` `roundStart` は、スキルではなくパッシブ・味方キャラ(`effects`)または敵の部位(`parts[].effects`)に書きます。付与先は自分自身です。
- `if` は条件です。`{ "hp": {"of":"target"|"self", "op":"<"|"<="|">"|">="|"=", "v":数値, "pct":true}, "sp": {同じ形式}, "check":"before"|"after" }` の形で、`hp` と `sp` は両方書けます(`pct:true` なら最大値に対する%)。
  - 体力の判定タイミング `check` は省略時 `before`(ダメージを与える前)で、`after` ならダメージの後です。
  - 精神力は常にダメージの前に判定し、幻想体の精神力は0として扱います。幻想体の体力は部位の耐久です。
- タイミングを持たないスキル効果(状態に応じて随時発動・停止するもの)は、`grants` ではなく耐性・バフなどの既存の処理で扱います。

### 敵

- `kind:"normal"`: 1部位で、体力と精神力があります。
- `kind:"abnormality"`: 体力共有・部位ごとの耐久で、精神力は持ちません(幻想体)。`destroyable` で部位を破壊可能にできます。
  - 敵本体に `sp` を書くと、精神力を全部位で共有する形になります(複数部位のねじれ用。部位ごとの精神力は持てません)。体力バーの横に丸で表示し、精神力の増減とパニックは全部位に同時に起こります。混乱と状態異常は部位ごとのままです。
- `skillSets:[{name, when, loop:[[スキルキー…],…]}]` で行動パターンを定義し、後ろにある条件一致が優先されます。
- `"noSp": true` で精神力を持たない敵になります(敵全体、または部位ごとに指定可で、部位の指定が優先)。精神力の表示が消え、精神力の増減は無視され、コインの表確率は常に50%になります。
- 部位ごとの設定: `slotWeight`(スロット加重値)、`priority`(優先度)、`effects`(戦闘開始時などの効果)。敵のスキル・耐性も味方と同じ形式です(`resist` は倍率)。
- イベント戦(負けイベなど): 敵に `endIf:{round, hpPct, hp, text}` を書くと、条件のどれか1つでも満たした時点で戦闘が終わり、勝敗ではなく「イベント終了」になります(`endIf` を書いた敵がいる場合だけ有効)。
  - `round`=Nラウンド終了時 / `hpPct`=その敵の体力がN%以下 / `hp`=その敵の体力がN以下(体力は敵全体の体力)。
  - 体力の条件は駒の処理ごとに判定するので、条件を満たした攻撃で倒れても勝利ではなくイベント終了になります。
  - `text` は終了時に画面へ出す文章です(省略可)。

## ルールの実装範囲

### 実装済み

- マッチ(威力同値は振り直し)、威力とダメージ計算(バフ枠×耐性枠・最低1)、精神力と表確率、速度順の処理、ラウンド終了処理。
- デッキ(1,1,1,2,2,3 の山札)。
- 状態異常(火傷/出血/振動/破裂/沈潜/呼吸/充電/特殊充電の一種である夢現/麻痺 ほか)。
- 混乱(体力閾値・多重)・振動爆発(スキル効果として自動発動)、パニック、E.G.O(覚醒・侵食・E.G.O侵食・E.G.Oパッシブ)。
- 守備スキル(防御=バリア / 回避=コイン単位で無効化 / 反撃)。
- 広域攻撃。
- 資源(7種)。
- 共鳴・完全共鳴。
- 処理タイミング(戦闘開始時・戦闘突入時・ターン開始時・使用時・攻撃前・マッチ勝利時・マッチ敗北・的中時・表面的中時・裏面的中時・対象討伐時)と、体力・精神力の条件、マッチ不可。効果の種類は、状態の付与とダメージ%の加算(与ダメージ・被ダメージ)。クリティカルダメージの加算(`critBonus`)。
- パッシブ・サポートパッシブの効果の自動発動(戦闘開始時・対象討伐時)。
- イベント戦(`endIf`)。

### 確定した扱い

混乱・パニック・精神力
- 混乱中に追加で閾値を越えた場合は、混乱レベルが加算される(最大で混乱++)。
- 混乱・離脱・パニック中は全スキル(守備を含む)が発動しない。
- 相手を倒した(仲間以外)と、倒したキャラの精神力が+10される。
- 精神力が-45になると、そのラウンドは通常どおり動け、次のラウンドからパニックになる(精神力は-45に固定され回復できない)。パニックはそのラウンドの終了時に解消し、精神力は0に戻る。ラウンドの開始時点で-45になった場合は、そのラウンドからパニックになる。パニック中はスキルを選択できず、混乱とは並行して数える。

守備スキル
- 反撃・防御・回避は「守備」扱いで、守備威力の増減が掛かる(攻撃威力・マッチ威力の増減は掛からない)。
- 防御・回避は敵スキルに合わせて発動し、反撃だけは最初に攻撃を受けた相手に発動する。
- 守備を合わせられなかった(合わせた敵が自分より速く、かつ自分を狙っていない)場合、その守備は何も起きない(カードは消費する)。守備(スキル0)は先に引いた方の手札を置き換えて消費する。
- 同じ敵スキルに複数人が合わせた場合は、あとから選んだ人が優先される。
- 守備は同じ部位への攻撃にだけ反応する。同じ部位に守備スキル駒が複数ある場合は、対象指定済み → 対象なし(ストック) → 左の駒の順に反応する。合わせた対象がいなくなった(倒れた・行動済み・行動不能)場合や、対象なしの防御・回避は、最初に受けた攻撃で発動する。
- 反撃は攻撃スキル1つにつき1回で、出血は発動しない。回避をコインごとに再使用しても使用時効果は毎回発生する。
- 敵の防御・回避は、GMが合わせた味方がその部位を攻撃したときに有効になる。敵の反撃は最初にコインが当たった相手に、ダメージが0でも発動する。

敵スキルセット
- 条件が複数一致した場合は、最後に書いたものを採用(仮。実装前に相談予定)。

資源(味方全員で共通・7種。`wrath lust sloth gluttony gloom pride envy`)
- スキルを使用すると、そのスキルの罪悪属性の資源が1増える。マッチに負けても増え、混乱などで不発になった場合や使用前に取り消された場合は増えない。
- 守備(防御・回避・反撃)は発動したときだけ増え、1ラウンドに1回まで。
- 戦闘終了まで保持し、上限はない。戦闘開始で0に戻る。
- 画面右の金枠に表示され、GMは「手動補助」から数を直せる。アイコンは `image/icon/sin/(罪悪名).png`。

共鳴(味方のみ・最終威力に加算。威力増加などと同じ扱いで、コインごと/マッチ時に加わります)
- 戦闘開始(開始ボタンを押した時点)の選択で判定し、行動不能の味方は除外します(並びも途切れません)。
- (罪悪名)共鳴: 同罪悪のスキルの個数だけを参照し、速度順(左から)で数えた同罪悪の何番目かで補正が決まります。3〜6番目は+1、7〜8番目は+2(1〜2番目は+0)。
- 完全共鳴: 同罪悪が3つ以上連続したとき、その連続数で決まります。3〜5個は+1、6〜7個は+2、8個は+3。
- 両方に当てはまる場合は補正値の大きいほうを使い、同じ値なら完全共鳴を表示します。守備スキルも対象です。
- スキル駒の左上に「(罪悪名)共鳴」「完全共鳴」のタグを表示します(選択中も見えます)。
- ラウンド開始時に行動不能(混乱・パニック)の味方は、速度に関わらず味方の並びの後ろ(戦闘不能の手前)に移り、その中では速度順です。速度の数字はそのまま表示します。

広域攻撃(攻撃スキルの `weight` が2以上)
- メインターゲットのほかにサブターゲットを自動で選びます。マッチ・守備の扱いはメインターゲットだけ従来どおりです。
- 予算は「攻撃加重値 − メインターゲットのスロット加重値」(敵が攻撃する場合は「攻撃加重値 − 1」)で、サブターゲットを選ぶたびにそのスロット加重値を消費します。予算が残る限り選び、重いスロットで超過しても構いません。候補が足りなければ少ないまま攻撃します。
- スロット加重値は部位ごとの `slotWeight`(整数、省略時1)で、敵の登録時に決まり戦闘中は変わりません。その部位のスロット(スキル駒・ブランク駒)すべてに同じ値が適用されます。優先度は部位の `priority`(省略時0、大きいほど先)で指定します。ブランク駒もスロットなので、サブターゲットになります。
- 味方の広域攻撃のサブターゲットは敵のスロット(スキル駒・ブランク駒)で、選ぶ順番は「同陣営から狙われている数が少ない → 優先度が高い → 左(速度順)」です。敵の広域攻撃のサブターゲットは生存している味方で、味方の並び順です。
- メインターゲットを選んだ時点でサブターゲットが決まり、以降は固定されます。使用時に倒れた・行動不能のサブターゲットは新しく選び直し、メインターゲットが倒れていれば不発になります。
- 同じ部位のスロットはサブターゲットとして別々に予算を消費しますが、ダメージは1コインにつき部位ごとに1回です。1コインのトスと威力は全員共通で、回避・耐性・出血などの判定は対象ごとに行い、クリティカルはコインごとに1回判定します。サブターゲットの防御・回避・反撃も反応します(反撃はシーケンス終了後)。
- マッチに負けた場合は攻撃が発生しません。矢印は、サブターゲットを点線(味方は青、敵は赤)で表示し、使用済みのサブターゲットは表示しません。

## 開発メモ

- ルール計算は `js/logic.js` に分離しており、DOM・通信に依存しません。`node test/sim.js` で乱数対戦を400回流して例外が出ないことを確認できます(`node test/sim.js one 7` でシード7の戦闘ログを表示)。
- 共有データは `rooms/<ルームID>/state` に1つのJSONとして保存されます。GMの操作は差分だけを書き込み、プレイヤーは自分の `units/<id>/choice` だけを書き込みます。
