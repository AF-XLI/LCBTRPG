# LCBTRPG戦闘システム

GitHub Pages(静的ホスティング)+ Firebase Realtime Database(無料のSparkプラン)で動く、最大8人程度向けの戦闘進行サイトです。ビルド作業は不要で、ファイルをそのまま置くだけで動きます。

## ファイル構成

| ファイル | 役割 |
| --- | --- |
| `index.html` | 画面の骨組み |
| `style.css` | 見た目(PC優先。スマホは暫定) |
| `config.js` | Firebase の接続情報(ここだけ書き換えます) |
| `js/logic.js` | ルール計算(画面に依存しない純粋なロジック。Node でも動作) |
| `js/store.js` | 共有(Firebase / ローカル)の通信部分 |
| `js/ui.js` | 画面の組み立て(HTML文字列を返すだけ) |
| `js/app.js` | 操作・同期・矢印/演出の制御 |
| `sample/party.json`, `sample/enemies.json` | サンプルデータ |
| `test/sim.js` | 自動対戦試験(`node test/sim.js`) |

## まず動かす(Firebase なし)

`config.js` が空のままだと「ローカルモード」になり、同じブラウザの複数タブ間だけで同期します。操作の確認用です。
`index.html` をブラウザで開く(または `python3 -m http.server` で配信する)→ ルームIDを入れて入室 → GMで入ると準備パネルが出ます。

※ サンプルの自動読み込みボタンは、`file://` で直接開いた場合は動きません。公開後のURL、またはローカルサーバー経由でお試しください(JSONの貼り付けはどちらでも可)。

## Firebase の設定(みんなで共有する場合)

1. [Firebase コンソール](https://console.firebase.google.com/) でプロジェクトを作成(Googleアナリティクスは不要)。料金プランは **Spark(無料)** のままで構いません。クレジットカードも不要です。
2. 「構築」→ **Realtime Database** → データベースを作成(ロケーションは近いもの。テストモードではなく **ロックモード** で開始)。
3. 「構築」→ **Authentication** → ログイン方法 → **匿名** を有効にする。
4. Realtime Database の「ルール」を次のように設定して公開する(ログインした人だけが読み書き可能)。
   ```json
   {
     "rules": {
       "rooms": {
         "$room": {
           ".read": "auth != null",
           ".write": "auth != null"
         }
       }
     }
   }
   ```
5. プロジェクトの設定 →「マイアプリ」→ ウェブアプリ(`</>`)を追加し、表示される `firebaseConfig` の値を `config.js` に転記する。`databaseURL` は Realtime Database の画面に表示されるURLです。
   ```js
   window.LC_FIREBASE_CONFIG = {
     apiKey: '…',
     authDomain: '…',
     databaseURL: 'https://xxxx-default-rtdb.asia-southeast1.firebasedatabase.app',
     projectId: '…',
     appId: '…',
     useAuth: true
   };
   ```
   `apiKey` はウェブ用の識別子で、公開されても問題ありません(守っているのは上記ルールです)。匿名認証を使わない場合は `useAuth: false` にし、ルールを `".read": true, ".write": true` に変えてください(URLを知っている人は誰でも書き込めます)。
6. Authentication → 設定 → 承認済みドメインに、公開先のドメイン(`ユーザー名.github.io`)を追加する。

### 無料枠の目安

Spark の Realtime Database は同時接続100・保存1GB・ダウンロード月10GB です。8人卓なら余裕があります。

## GitHub Pages で公開する

1. この一式をリポジトリのルートに置いて push する。
2. リポジトリの Settings → Pages → Branch を `main` / `/ (root)` にして保存する。
3. 数分後に `https://ユーザー名.github.io/リポジトリ名/` で開けます。
4. 卓の参加者には、ルームIDを伝えてください(`…/?room=ルームID` のURLを共有しても入室できます)。

## 遊び方

役割は入室時に選びます。

- **GM**: 準備パネルで味方/敵のJSONを読み込み、戦闘を開始します。敵の行動決定(敵のスキル駒を押し、次に味方の駒を押して対象を選択。敵の防御・回避は「合わせる味方」を選びます。反撃は対象なし。スキルの手動変更も可)、ラウンドの進行(戦闘開始 → 1手進める/自動進行 → 次のラウンド)、体力・精神力・状態・振動爆発・E.G.O・復帰などの手動補助を行います。
- **プレイヤー**: 上部で操作キャラを選び、自分の駒(速度の上)を押してスキルを選択 → 敵のスキル駒を押して対象を決める → 画面下の「確定する」。守備(防御・回避)も、合わせる敵の攻撃スキル枠を選びます。反撃は対象を選びません。
- **観戦**: 見るだけです。

1ラウンドの流れ: `敵の行動決定(GM)` → `味方の行動選択` → `戦闘処理(速度順)` → `ラウンド終了`。

画面の見かた(PC版。スマホ版は後日調整予定で、現在は縦に並べて使える程度です):

- 上部の赤い帯: 中央にラウンドと段階、右に「確定 x / y」と、GMには次に押すボタン(戦闘開始 / 1手進める / 次のラウンドへ)。
- 敵は上段に、名前・体力バー・精神力バー・立ち絵・スキル駒の順で並びます。異常体は、スキル駒を押すと全体の体力バーが、その部位の耐久バーと精神力バーに切り替わります(余白を押すと戻る)。
- 味方は下段に速度の速い順で並び、スキル駒(未選択はブランク)・速度(黄色)・体力リング(左下の数字が体力、右下の丸が精神力)・確定状況が出ます。
- 矢印: 金=マッチ(矢じりがぶつかる位置に火花。守備を合わせた場合は火花なし)/ 赤=敵の一方攻撃 / 水色=味方の一方攻撃 / 点線=未確定。右パネルの「矢印の表示」で切り替えられます。
- 敵のスキル駒や部位を押すと詳細が出ます。体力バーの黄色い線は混乱の閾値です。
- ログは戦闘開始時に窓で開き、そのラウンドの分だけを表示します(右上の「ログ」でも開閉できます)。
- 敵の速度は、敵スキル駒の上に表示されます。
- 敵の並びは準備パネルの「敵の配置(左から)」で決め、戦闘中は動きません。撃破された敵は詰めて表示されます。

## JSON の形式

味方は `sample/party.json`、敵は `sample/enemies.json` を見本にしてください。要点:

- 味方: `name, maxHp, sp(精神力), speed:[最小,最大], thr:[混乱閾値(%)…], resist(耐性), skills{0〜3}`。`skills.0` が守備(`kind:"defense"` の `sub` は `guard`=防御 / `evade`=回避、または `kind:"counter"`)、1〜3 が攻撃スキル。
- スキル: `name, kind, sin(罪悪), phys(物理), tier, base, coins:[各コインの加算], text, grants[]`。`grants` は `{status, p(威力), c(回数) または v(値), to:"target"|"self", when:"hit"|"use", coin:N, next:true}`。
- 状態の ID: `burn bleed vibration rupture sinking breath charge trance paralysis bind dmgUp dmgDown fragile protect powerDown quick powerUp ...`(`js/logic.js` の `STATUS` 参照)。
- 敵: `kind:"normal"`(1部位・体力と精神力あり)/ `"abnormality"`(体力共有・部位ごとに耐久と精神力。`destroyable` で破壊可能)。`skillSets:[{name, when, loop:[[スキルキー…],…]}]` で行動パターンを定義し、後ろにある条件一致が優先されます。
- 精神力を持たない敵は `"noSp": true` を指定します(敵全体、または部位ごとに指定可。部位の指定が優先)。精神力の表示が消え、精神力の増減は無視され、コインの表確率は常に50%になります。
- 条件付きダメージ補正は `dmgBonusIf`、スキル差し替えは `replace`、条件分岐は `branches` を使います。
- パッシブ・サポートパッシブ: 味方に `passives:[{name, text, need, icon}]` と `supportPassives:[…]`(同じ形式)を書くと、画面左の金枠に並びます(パッシブが上、サポートパッシブが下)。`need` は「資源×n保有」の条件で `{"pride": 3}` のように書き、足りない間はアイコンが暗くなります(省略すると常に明るい)。共鳴で発動する場合は `reso` に `{"wrath": 3}` のように「罪悪名×n共鳴」を書きます(同ラウンドに味方が使う同罪悪のスキルがn個以上で発動。位置は問わず、戦闘開始時に判定。`need` と併記すると両方が必要)。`icon` は画像のパスで、省略するとキャラ名の頭文字を表示します。アイコンを押すと説明が出ます。

## ルールの実装範囲

実装済み: マッチ(威力同値は振り直し)、威力とダメージ計算(バフ枠×耐性枠・最低1)、精神力と表確率、状態異常(火傷/出血/振動/破裂/沈潜/呼吸/充電/特殊充電の一種である夢現/麻痺 ほか)、混乱(体力閾値・多重・振動爆発)、デッキ(1,1,1,2,2,3 の山札)、守備スキル(防御=バリア / 回避=コイン単位で無効化 / 反撃。防御・回避は敵スキルに合わせて発動し、反撃だけは最初に攻撃を受けた相手に発動。敵の防御・回避は、GMが合わせた味方がその部位を攻撃したときに有効になり、敵の反撃は最初にコインが当たった相手に、ダメージが0でも発動する)、速度順の処理、ラウンド終了処理。

### 確定した扱い

- 混乱中に追加で閾値を越えた場合は、混乱レベルが加算される(最大で混乱++)。
- 混乱・離脱・パニック中は全スキル(守備を含む)が発動しない。
- 反撃・防御・回避は「守備」扱いで、守備威力の増減が掛かる(攻撃威力・マッチ威力の増減は掛からない)。
- 守備を合わせられなかった(合わせた敵が自分より速く、かつ自分を狙っていない)場合、その守備は何も起きない(カードは消費する)。守備(スキル0)は先に引いた方の手札を置き換えて消費する。
- 同じ敵スキルに複数人が合わせた場合は、あとから選んだ人が優先される。
- 守備は同じ部位への攻撃にだけ反応する。同じ部位に守備スキル駒が複数ある場合は、対象指定済み → 対象なし(ストック) → 左の駒の順に反応する。合わせた対象がいなくなった(倒れた・行動済み・行動不能)場合や、対象なしの防御・回避は、最初に受けた攻撃で発動する。反撃は攻撃スキル1つにつき1回で、出血は発動しない。回避をコインごとに再使用しても使用時効果は毎回発生する。
- 相手を倒した(仲間以外)と、倒したキャラの精神力が+10される。
- 精神力が-45になるとパニックになり、精神力は-45に固定され回復できない。ラウンドの途中なら次のラウンド終了時、ラウンド開始時なら同ラウンド終了時に解消し、精神力は0に戻る。パニック中はスキルを選択できず、混乱とは並行して数える。

- 敵スキルセットの条件が複数一致した場合は、最後に書いたものを採用(仮。実装前に相談予定)。
- 資源(味方全員で共通・7種。`wrath lust sloth gluttony gloom pride envy`): スキルを使用すると、そのスキルの罪悪属性の資源が1増えます。マッチに負けても増え、混乱などで不発になった場合や使用前に取り消された場合は増えません。守備(防御・回避・反撃)は発動したときだけ増え、1ラウンドに1回までです。戦闘終了まで保持し、上限はありません。戦闘開始で0に戻ります。画面右の金枠に表示され、GMは「手動補助」から数を直せます。アイコンは `image/icon/sin/(罪悪名).png` です。

### 未実装(手動補助で対応)

- 処理タイミング(「◯◯時」)の自動化、広域スキル/広域乱射
- 共鳴(味方のみ・最終威力に加算。威力増加などと同じ扱いで、コインごと/マッチ時に加わります): 戦闘開始(開始ボタンを押した時点)の選択で判定し、行動不能の味方は除外します(並びも途切れません)。
  - (罪悪名)共鳴: 同罪悪のスキルの個数だけを参照し、速度順(左から)で数えた同罪悪の何番目かで補正が決まります。3〜6番目は+1、7〜8番目は+2(1〜2番目は+0)。
  - 完全共鳴: 同罪悪が3つ以上連続したとき、その連続数で決まります。3〜5個は+1、6〜7個は+2、8個は+3。
  - 両方に当てはまる場合は補正値の大きいほうを使い、同じ値なら完全共鳴を表示します。守備スキルも対象です。
  - スキル駒の左上に「(罪悪名)共鳴」「完全共鳴」のタグを表示します(選択中も見えます)。
  - ラウンド開始時に行動不能(混乱・パニック)の味方は、速度に関わらず味方の並びの後ろ(戦闘不能の手前)に移り、その中では速度順です。速度の数字はそのまま表示します。
- E.G.O の使用コストと効果(耐性の上書きのみ。GMの手動補助から実行)。資源をコストにする処理もこれから
- パッシブの効果の自動発動(資源が足りているかは、アイコンの明暗の表示のみ)
- モバイル版の資源・パッシブ欄(今は画面の上に横並びで表示。ツマミで出し入れする形は今後実装)
- 特殊精神力増減(人格・敵ごとの条件)、敵の回復・召喚・復帰(スキル・パッシブの効果として記載する予定。GMの手動補助で対応)
- 特殊充電(充電の派生カテゴリ)の他の型(「威力のみ・威力を消費する型」など)。充電と同一仕様の型である夢現は実装済み
- マッチ勝率の表示(`LC.winProb` で計算のみ実装済み。出血・途中中断は無視し、麻痺があれば全コインの加算を0とみなす)

## 開発メモ

- ルール計算は `js/logic.js` に分離しており、DOM・通信に依存しません。`node test/sim.js` で乱数対戦を400回流して例外が出ないことを確認できます(`node test/sim.js one 7` でシード7の戦闘ログを表示)。
- 共有データは `rooms/<ルームID>/state` に1つのJSONとして保存されます。GMの操作は差分だけを書き込み、プレイヤーは自分の `units/<id>/choice` だけを書き込みます。
